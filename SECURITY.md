# Security

## Основные правила

Не использовать реальные персональные данные.

Не публиковать экзаменационные работы пользователей.

Использовать только синтетические данные в репозитории.

---

## Контроль доступа

Для MVP:

- без регистрации;
- без хранения персональных данных.
- Доступ осуществляется анонимно (на этапе исследовательского прототипа).

---

## Блокеры для публичного деплоя

Перед запуском публичного режима интегратор **обязан** закрыть следующие блокирующие риски или явно отказаться от запуска публичного режима:

1. **Аутентификация и авторизация (RBAC)**: Внедрить систему контроля доступа. Текущий анонимный доступ недопустим для работы с реальными экзаменационными работами и результатами.
2. **Rate Limiting (Защита от злоупотребления ресурсами)**: Ограничить частоту вызовов, особенно для ресурсоемких операций (OCR, LLM), для предотвращения отказа в обслуживании (DoS) и неконтролируемых расходов.
3. **Безопасность инфраструктуры**:
    - Настроить балансировщик нагрузки (Nginx) с жесткими лимитами на размер запроса (`client_max_body_size`) и таймаутами.
    - Провести аудит зависимостей (SAST) и сканирование Docker-образов на известные уязвимости.
    - Убедиться, что `DEBUG=False` и настроены строгие правила CORS.
4. **Правовые вопросы**: Утвердить политику обработки персональных данных и правила хранения/удаления файлов.

*Полный отчет по безопасности находится в `docs/security/security-review.md`.*
