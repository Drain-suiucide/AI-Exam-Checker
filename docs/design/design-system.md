# Design System — AI Exam Checker

## 1. Контекст и задача

Концепция интерфейса ориентирована на конкурсную демонстрацию исследовательского MVP системы для проверки развернутых ответов по истории. Основная цель — быстро показать, как именно работает проверка: загрузка ответа, OCR, выравнивание текста, оценка по критериям, объяснение решения, а также прозрачность ограничений и статуса экспертизы.

Целевая аудитория:
- ученик или пользователь, который демонстрирует процесс проверки;
- эксперт, анализирующий предварительную оценку;
- жюри конкурса, которому нужно быстро понять ценность решения.

## 2. Принципы дизайна

### 2.1. Прозрачность вместо иллюзии автоматизма
Интерфейс должен показывать не только итоговую оценку, но и:
- откуда она взялась;
- какие фрагменты ответа были распознаны;
- какие критерии применены;
- когда решение требует экспертной проверки.

### 2.2. Сильная иерархия информации
Разные уровни важности разделены визуально:
- навигация и статус сценария;
- основная форма ответа;
- блок результата;
- пояснения, ограничения и опасения.

### 2.3. Визуальная уверенность без излишней «премиальности»
Сайт должен выглядеть как современный образовательный SaaS, но исключать признаки фальшивой официальности или коммерческого продукта в государственном секторе. Визуальный язык — современный, профессиональный, спокойный.

## 3. Визуальная система

### 3.1. Основная палитра

- Primary / brand: `#1D4ED8` — синий, основной CTA и структурный акцент;
- Primary dark: `#163EA6` — для hover/pressed и активных навигационных состояний;
- Accent: `#10B981` — успех, подтверждение и позитивный статус;
- Warning: `#F59E0B` — предупреждения и спорные элементы;
- Error: `#DC2626` — критические ошибки и недоступность;
- Neutral 900: `#111827` — основной текст;
- Neutral 700: `#374151` — вторичный текст;
- Neutral 500: `#6B7280` — метки и подсказки;
- Neutral 200: `#E5E7EB` — разделители;
- Neutral 100: `#F3F4F6` — фоновые панели;
- Surface White: `#FFFFFF` — рабочая форма;
- Surface Soft: `#F8FAFC` — общий фон интерфейса.

### 3.2. Типографика

Шрифтовая система: современный sans-serif без засечек.

- H1: 36/44, Semibold, letter-spacing: -0.02em;
- H2: 28/36, Semibold;
- H3: 22/30, Semibold;
- Body L: 18/28, Regular;
- Body M: 16/24, Regular;
- Small: 14/20, Medium/Regular;
- Label: 12/16, Medium, uppercase in UI labels when needed.

### 3.3. Сетка и отступы

- Базовый шаг сетки: 8px;
- Контейнер: max-width 1200px;
- Карточки: 24px padding desktop, 16px mobile;
- Разрыв между секциями: 48–64px;
- Между блоками внутри карточки: 16–24px.

### 3.4. Скругления

- Buttons / controls: 12px;
- Cards: 16px;
- Modals / panels: 20px;
- Focus ring: 3px offset, 2px ring radius, blue accent.

### 3.5. Тени

Используются мягкие тени, не более двух уровней:
- Level 1: shadow 0 8px 24px rgba(17, 24, 39, 0.08);
- Level 2: shadow 0 20px 44px rgba(17, 24, 39, 0.12).

## 4. Компоненты

### 4.1. Header
- Логотип: графический маркер + слово AI Exam Checker;
- Навигация: Главная, Проверка, Методика, Ограничения;
- CTA: «Загрузить ответ» или «Проверить ответ»;
- В статусе на демонстрационных страницах желательно показывать «MVP / История, ЕГЭ, задание 19».

### 4.2. Steps / progress
- Два режима: линейный прогресс для сценария и компактный индикатор для мобильных экранов;
- Состояния: current, complete, pending, error;
- Номера шагов: 1–6 по основному сценарию.

### 4.3. Cards
- Основной контейнер для формы и результатов;
- Отдельный блок criteria summary;
- Оценочный блок с наборами KPI.

### 4.4. Buttons
- Primary: blue, high contrast, prominent;
- Secondary: white/neutral with border;
- Ghost: no background, only text when less emphasis needed;
- Destructive / warning: red / amber for errors.

### 4.5. Form controls
- Условия выбора предмета, экзамена, года, задания;
- File upload area with drag-and-drop support;
- Textarea with OCR edit controls;
- Toggle chips for metadata filters and evidence tags.

### 4.6. Data visualization / badges
- Score pills: 0, 1, 2 балла, with color-coded states;
- Confidence indicator: soft gauge or small progress bar;
- Status badges: “Требуется экспертная проверка”, “Низкая уверенность”, “Ожидание OCR”.

## 5. Состояния интерфейса

### 5.1. Загрузка
- Spinner + label;
- Текст: «Распознаем текст и проверяем ответ…»;
- Использовать мягкие анимации длительностью 200–400ms, без лишних сложных эффектов.

### 5.2. Успех
- Основной цвет — blue и green;
- Показывать итоговую сумму и пояснение;
- Использовать визуальные маркеры валидации.

### 5.3. Ошибка
- Красный акцент и понятный текст;
- Указывать причину: неподдерживаемый формат, сервер недоступен, поиск ответа не дал результата;
- Обязательно предложить следующее действие.

### 5.4. Expert review required
- Жёлтый/оранжевый статус с понятным объяснением;
- Текст: «Автоматическая оценка не уверена в корректности интерпретации. Требуется экспертная проверка»;
- Не подменять это полноценной экспертной оценкой.

## 6. Адаптивность

### Desktop
- 3-column layout for overview and result content where appropriate;
- Main actions remain visible in header and sticky sticky elements for step-based workflow.

### Tablet
- Stack summary cards vertically;
- Reduce padding to 16px;
- Maintain left/right alignment for primary actions.

### Mobile
- Single-column flow;
- Reflow step indicator to compact horizontal progress;
- Buttons become full width when necessary;
- Keep evidence and score cards easy to tap with 44px minimum touch targets.

## 7. Иллюстрации и графические материалы

Используются простые, оригинальные SVG-иллюстрации, а не фотоснимки и сторонние изображения.

Рекомендованные файлы:
- `images/hero-illustration.svg` — основной герой-баннер для главной страницы;
- `images/scan-workflow.svg` — схема загрузки/проверки/результата.

Для каждой иллюстрации сохраняется ясная цель, масштабируемость и контраст на светлом фоне.

## 8. Речевой стиль и тексты интерфейса

Тексты должны быть:
- краткими;
- понятными без профессионального жаргона;
- нейтральными и без лишней уверенности;
- прозрачными в отношении ограничений.

Примеры:
- «Загрузите ответ или вставьте текст вручную»;
- «Проверка выполнена по подтверждённой конфигурации»;
- «Автоматическая оценка — предварительная»;
- «Пояснение основано на выделенных фрагментах ответа»;
- «Требуется экспертная проверка: не все признаки оценки достаточно уверены».

## 9. Допустимые ограничения

- Не добавлять поддельные критерии или неутверждённые баллы;
- Не использовать официальные государственные эмблемы или визуальный язык существующих госпорталов;
- Не вкрадываться в пользовательский контент лишней рекламой;
- Не смешивать состояние результата с реальной экспертной оценкой.

## 10. Рекомендации для реализации

Для фронтенд-реализации при работе с React + TypeScript наиболее рационально использовать:
- CSS Modules or Tokens;
- component library based on design tokens;
- reusable card, stepper, status badge, criteria-table, panel, alert components.

Структура компонентов должна поддерживать:
- step-based UX;
- multiple status states;
- evidence highlight;
- compact mobile view;
- accessibility-first semantics.

## 11. Краткое резюме

UI для AI Exam Checker должен выглядеть как современный и доверительный инструмент исследования, а не как «псевдоофициальная проверка» или визуальная имитация проверки ЕГЭ. Ключевая ценность — не каскад эффектов и анимации, а ясность объяснения, прозрачность ограничений и аккуратный UX, который помогает понять, как система работает на практике.
