# Управление процессом экспертной проверки (Expert Review Workflow)

Этот документ описывает процесс ручной проверки результатов автоматического оценивания (OCR и AI) человеком-экспертом. Процесс гарантирует безопасность данных, аудит решений и разделение автоматических и экспертных оценок.

## 1. Конечный автомат состояний (State Machine)

Процесс обработки каждой работы проходит через строго заданные состояния.

### Перечень статусов
1. `RECEIVED` - Изображение ответа загружено, ожидание начала обработки.
2. `OCR_PENDING` - Работа в очереди на распознавание текста (OCR).
3. `TRANSCRIPTION_REVIEW` - Распознанный текст требует проверки экспертом (низкая уверенность модели или ручной триггер).
4. `READY_FOR_EVALUATION` - Текст утвержден, ожидание автоматической оценки AI.
5. `EVALUATION_PENDING` - Работа в очереди на оценку LLM.
6. `REVIEW_REQUIRED` - Оценка завершена, но требует проверки экспертом (спорный результат).
7. `REVIEW_IN_PROGRESS` - Эксперт взял работу на проверку (блокировка для других экспертов).
8. `COMPLETED` - Обработка завершена, финальный балл установлен (автоматически или экспертом).
9. `FAILED` - Критическая ошибка обработки (нечитаемое изображение, сбой модели).

### Матрица переходов

| Исходный статус | Действие | Роль | Конечный статус | Запись аудита |
| :--- | :--- | :--- | :--- | :--- |
| `RECEIVED` | Запуск пайплайна | `system` | `OCR_PENDING` | System: Запуск OCR |
| `OCR_PENDING` | Завершение OCR (уверенность высокая) | `system` | `READY_FOR_EVALUATION` | System: OCR успешен |
| `OCR_PENDING` | Завершение OCR (уверенность низкая) | `system` | `TRANSCRIPTION_REVIEW` | System: Требуется проверка текста |
| `TRANSCRIPTION_REVIEW` | Эксперт правит текст | `expert` | `READY_FOR_EVALUATION` | Expert ID: Текст скорректирован (сохранение Diff) |
| `READY_FOR_EVALUATION` | Запуск AI-оценки | `system` | `EVALUATION_PENDING` | System: Запуск оценки |
| `EVALUATION_PENDING` | Оценка завершена (высокая уверенность) | `system` | `COMPLETED` | System: Оценка успешна |
| `EVALUATION_PENDING` | Оценка завершена (триггер проверки) | `system` | `REVIEW_REQUIRED` | System: Требуется экспертная оценка |
| `REVIEW_REQUIRED` | Эксперт открывает работу | `expert` | `REVIEW_IN_PROGRESS` | Expert ID: Начата проверка |
| `REVIEW_IN_PROGRESS` | Эксперт принимает оценку | `expert` | `COMPLETED` | Expert ID: Оценка AI подтверждена |
| `REVIEW_IN_PROGRESS` | Эксперт изменяет оценку | `expert` | `COMPLETED` | Expert ID: Оценка изменена (прежнее значение, новое значение, обоснование) |
| `REVIEW_IN_PROGRESS` | Эксперт возвращает на OCR | `expert` | `TRANSCRIPTION_REVIEW`| Expert ID: Возврат на распознавание (обоснование) |
| `REVIEW_IN_PROGRESS` | Эксперт отменяет проверку | `expert` | `REVIEW_REQUIRED` | Expert ID: Проверка прервана |
| *Любой статус* | Ошибка обработки | `system` | `FAILED` | System: Ошибка (код ошибки) |

## 2. Триггеры ручной проверки (Reasons for Review)

Система переводит работу в статус `REVIEW_REQUIRED` при следующих условиях:
- Низкая уверенность LLM при выставлении оценки.
- Существенное расхождение в баллах между разными AI-судьями (если используется ансамбль).
- Присутствие стоп-слов или подозрение на списывание/галлюцинации в ответе.
- Оценка пограничная (например, 0 баллов за задание, где типично набирают больше).

## 3. Данные для эксперта (UX & UI Context)

При проверке (`REVIEW_IN_PROGRESS`) эксперту должны быть доступны:
1. **Исходное изображение** (в высоком разрешении, с возможностью увеличения).
2. **Распознанный текст** (транскрипция).
3. **Задание и Критерии** (версионированные — те самые, по которым работала модель).
4. **Предварительный результат (AI)**:
   - Общий балл.
   - Детализация по каждому критерию с текстовым обоснованием от AI.

*Важно:* Эксперт не имеет права редактировать сами критерии в этом интерфейсе. Интерфейс должен явно маркировать результаты как "Предварительные (AI)".

## 4. Действия эксперта и Аудит

При изменении балла или возврате работы, система требует **текстовое обоснование**.

Структура Audit Log записи:
- `timestamp`: Время изменения
- `user_id`: Идентификатор эксперта
- `action`: Тип действия (`SCORE_MODIFIED`, `AI_SCORE_ACCEPTED`, `RETURN_TO_OCR`)
- `previous_state`: JSON с предыдущими оценками AI
- `new_state`: JSON с экспертными оценками
- `reasoning`: Текст обоснования эксперта
- `entity_id`: ID работы

Автоматический результат AI сохраняется навсегда в отдельном поле `ai_evaluation_result` базы данных и никогда не затирается. Экспертный результат пишется в `expert_evaluation_result`, а итоговый балл (отдаваемый пользователю) берется из `final_evaluation_result`.

## 5. Безопасность и Конкурентность

- **Изоляция данных:** Неавторизованные пользователи (ученики) имеют доступ только к итоговому баллу и обезличенным комментариям. Чувствительные данные (имена других учеников, внутренние логи) не передаются на клиент.
- **Блокировка:** При переходе в `REVIEW_IN_PROGRESS` работа блокируется (через поле `locked_by` и `locked_at`). Другой эксперт не может начать проверку этой работы.
- **Оптимистичные блокировки (Optimistic Concurrency Control):** При сохранении результата проверяется версия документа (`version`), чтобы избежать перезаписи при одновременном редактировании.
- **Неизменяемость истории:** Логи аудита работают только на добавление (append-only).
