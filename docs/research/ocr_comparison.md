# Сравнение OCR/HTR-решений для AI Exam Checker

Дата исследования: 2026-10-29.
Статус: решение принято, см. § «Вывод».

## 1. Задача и критерии выбора

Нужен движок, который извлекает текст из изображений ответов (печатных и рукописных) и возвращает
не только строку, но и привязку к изображению: координаты фрагментов и оценку уверенности. Это
требование контракта (`API_CONTRACT.md` §2.3, поле `ocr.segments[].bbox` и `confidence`): пользователь
должен видеть, где именно на скане находится распознанный фрагмент, и править текст до оценивания.

Критерии, по которым сравнивались решения:

| # | Критерий | Почему важен |
|---|---|---|
| K1 | Русский печатный текст | основной сценарий: фото/скан бланка |
| K2 | Русский рукописный текст | ответы ЕГЭ пишутся от руки |
| K3 | Локальный запуск без передачи данных | в ответах могут быть ФИО и почерк; вынос за периметр недопустим без отдельного решения |
| K4 | Лицензия | проект распространяется как MIT; нужна совместимость |
| K5 | Координаты + уверенность | требование контракта |
| K6 | Воспроизводимость | фиксированные версии движка и модели |
| K7 | Стоимость | прототип, ограниченный бюджет |
| K8 | Системные требования | должна быть возможность запуска в CI и на ноутбуке |

## 2. Рассмотренные решения

### 2.1 Tesseract 5 (через `pytesseract`)

**Что это.** Классический OCR-движок с LSTM-распознавателем. В версии 5 используется
`tessdata_fast`/`tessdata_best` — нейросетевые модели на базе LSTM.

**Русский язык.**
- Печатный: да, официальная модель `rus.traineddata` из `tessdata_fast`/`tessdata_best`.
- Рукописный: **нет**. Tesseract не содержит обученной модели для русского рукописного текста.
  Модели `script/Cyrillic` и `script/Russian` относятся к печатному тексту. На рукописном вводе
  движок выдаёт мусор (подтверждается внешними замерами, см. §3).

**Лицензия.**
- Движок: Apache-2.0.
- `tessdata_fast`/`tessdata_best`: Apache-2.0 (README репозитория: «All data in the repository are
  licensed under the Apache-2.0 License»).
- `pytesseract` 0.3.13: Apache-2.0 (проверено в метаданных установленного пакета).
- Совместимо с MIT-проектом.

**Возможности, релевантные контракту.**
- `image_to_data(..., output_type=DICT)` возвращает по каждому слову: `text`, `conf` (0–100),
  `left`, `top`, `width`, `height`, `block_num`, `par_num`, `line_num`, `word_num`.
- Этого достаточно, чтобы собрать `segments[]` с `char_start`/`char_end` и нормализованным `bbox`.
- `conf = -1` у строк, где текст не распознан, — нужно фильтровать.

**Системные требования.**
- Нативный бинарник `tesseract` + каталог `tessdata` с моделями (`rus` ≈ 3.9 МБ в `tessdata_fast`).
- CPU достаточно; GPU не нужен.
- Пакет `pytesseract` требует только `packaging` и `Pillow`.
- Модель можно положить в локальный каталог и указать через `TESSDATA_PREFIX`, не трогая систему.

**Ограничения.**
- Ошибки на тонких деталях, критичных для истории: римские цифры путаются с кириллицей
  (`II` → `П`, воспроизведено на собственном прогоне, см. §3.1).
- Чувствителен к наклону, бликам, низкому контрасту; нужна предобработка.
- Уверенность не откалибрована: `conf=96` не означает «верно». Это подтверждает требование
  контракта не трактовать confidence как вероятность правильности.
- Не поддерживает рукописный текст.

**Передача данных третьим лицам:** отсутствует, всё локально.
**Воспроизводимость:** высокая — версия движка и файл модели фиксируются; вывод детерминирован
при одинаковых параметрах.

### 2.2 EasyOCR

**Что это.** Обёртка над PyTorch: детектор CRAFT + распознаватель CRNN (ResNet/VGG + LSTM + CTC).

**Русский язык.** Кириллица заявлена в списке поддерживаемых письменностей (80+ языков).
**Рукописный текст: не поддерживается.** В README проект сам относит «Handwritten text support»
к разделу «What's coming next», то есть к планам, а не к текущим возможностям.

**Лицензия:** Apache-2.0.

**Системные требования.** PyTorch + torchvision (на Windows — отдельная установка под CUDA/CPU),
модели скачиваются при первом запуске. Существенно тяжелее Tesseract: сотни мегабайт зависимостей,
заметное потребление ОЗУ, недетерминированность при CPU-инференсе в некоторых конфигурациях.

**Ограничения.**
- Рукопись не поддерживается — тот же принципиальный пробел, что у Tesseract.
- Тяжёлые зависимости нежелательны для прототипа и CI.
- В независимом бенчмарке (см. §3) на рукописи CER 58.0% — хуже Tesseract по скорости и не лучше
  по качеству для нашей задачи.

**Передача данных:** локально, но модели скачиваются с внешнего хоста при первом запуске —
это нужно учитывать в закрытом контуре (требуется предварительная загрузка моделей).

---

### 2.3 PaddleOCR

**Что это.** Фреймворк Baidu: детекция (DB) + распознавание (CRNN/SVTR), плюс линейка VLM-моделей
(PaddleOCR-VL).

**Русский язык.**
- PP-OCRv5 multilingual recognition покрывает 109 языков, включая кириллицу.
- PP-OCRv6 — унифицированная модель на 50 языков латиницы/китайского/японского, **кириллицы в ней
  нет** — это важно: при обновлении версии можно потерять русский язык.
- Отдельной русской модели нет, кириллица идёт в составе мультиязычной.

**Лицензия:** Apache-2.0.

**Системные требования.** PaddlePaddle 3.1.x, Python 3.8–3.12, CPU/GPU. Существенно тяжелее
Tesseract по зависимостям.

**Ограничения.**
- Рукописный русский: PP-OCR — детекция+распознавание печатного/сценического текста; для рукописи
  нет отдельно заявленной поддержки. PaddleOCR-VL (VLM) теоретически может читать рукопись, но это
  уже генеративная модель со всеми рисками галлюцинаций — для транскрипции экзаменационного ответа
  это нежелательно без отдельного согласованного этапа.
- Тяжёлая установка, чувствительность к версиям PaddlePaddle.

**Передача данных:** локально.

---

### 2.4 Специализированные HTR-модели (TrOCR)

**Что это.** TrOCR — encoder-decoder (BEiT-энкодер + RoBERTa-декодер), работает построчно:
на вход кроп строки, на выход строка текста.

**Русские модели, найденные на Hugging Face:**

| Модель | База | Данные | Заявленный CER | Лицензия |
|---|---|---|---|---|
| `kazars24/trocr-base-handwritten-ru` | `microsoft/trocr-base-handwritten` | Cyrillic Handwriting Dataset (73 830 кропов, русский) | 0.0485 (валидация) | **не указана** на карточке |
| `cyrillic-trocr/trocr-handwritten-cyrillic` | `kazars24/...` | ~6 800 изображений из Transkribus (церковнославянский/русский/украинский) | 0.2533 (валидация) | MIT |

**Существенные оговорки.**
- У лучшей по метрике модели **лицензия не указана** — использовать её в проекте нельзя без
  уточнения у автора. Это блокирующий фактор.
- Модель с MIT-лицензией имеет CER 25% на валидации и сама предупреждает о некорректных
  ground-truth аннотациях.
- TrOCR работает **построчно**: нужен отдельный детектор строк. Это отдельный компонент,
  который тоже надо выбирать, обучать и валидировать.
- Модель обучена на кропах строк — на полностраничном скане без детекции работать не будет.
- Метрики на валидации автора не переносятся на реальные сканы ответов (другой домен: тетрадный
  лист, ручка, освещение).

**Вывод по направлению:** перспективно для рукописи, но требует (а) решения по лицензии,
(б) детектора строк, (в) собственной валидации на целевом домене. Это отдельный этап, а не
стартовая реализация.

---

### 2.5 Облачные OCR (отдельный анализ: приватность, цена, условия)

Рассматривались как **отдельная опция**, а не как кандидат по умолчанию, поскольку ответы могут
содержать персональные данные.

| Сервис | Русский печатный | Русский рукописный | Цена (ориентир) | Передача данных |
|---|---|---|---|---|
| Yandex Vision OCR | да | да, отдельная модель «handwriting» | печатный ≈ $1.08 / 1000 стр.; рукописный ≈ $12.46 / 1000 стр. | изображение уходит в облако |
| Google Cloud Vision | да | ограниченно (Document Text Detection) | ≈ $1.50 / 1000 ед. после 1000 бесплатных в месяц | изображение уходит в облако |
| Azure AI Vision | да | ограниченно | тарифицируется по транзакциям | изображение уходит в облако |
| AWS Textract | да | ограниченно | по страницам | изображение уходит в облако |

**Приватность и условия.**
- Любой облачный OCR означает передачу изображения ответа третьей стороне. Для экзаменационных
  работ с ФИО, почерком и потенциально чувствительным содержанием это требует отдельного решения
  и согласия, а не технического выбора по умолчанию.
- Условия хранения и использования данных для обучения различаются между провайдерами и меняются;
  на момент исследования официальные страницы политик не дали однозначно проверяемых формулировок
  в машинночитаемом виде. **Любое использование облака требует юридической проверки до включения.**
- Цена рукописного распознавания у Yandex (~$12.46/1000 стр.) на порядок выше печатного — при
  массовой проверке это значимая статья расходов.

**Вывод:** облачные сервисы — единственный из рассмотренных вариантов с production-качеством
русской рукописи «из коробки», но они несовместимы с требованием локальной обработки без отдельного
согласованного решения. В кодовой базе они не реализуются; фиксируются как возможный будущий
адаптер за тем же интерфейсом.

## 3. Собственные измерения

### 3.1 Проверка Tesseract 5.4.0 на синтетическом изображении

Окружение: Windows 11, Tesseract 5.4.0.20240606 (UB-Mannheim), `tessdata_fast` `rus` + `eng`,
шрифт Times New Roman 32 px, белый фон, чёрный текст, `--psm 6`.

Эталон:
```
Понятие «реформа» раскрыто.
Александр II провёл реформу 1861 года.
```

Получено:
```
Понятие «реформа» раскрыто.

Александр П провёл реформу 1861 года.
```

Наблюдения:
- Если использовать только модель `rus`, римская цифра `II` распознаётся как `П` (кириллическая «П»). При конфигурации `rus+eng` эта проблема решается.
  Это ровно тот класс ошибок, который критичен для истории: «Александр II» и «Александр III»
  различаются одной цифрой, а ошибка меняет исторический факт.
- `conf` для ошибочного слова был 92–93 — то есть **высокая уверенность при неверном результате**.
  Это прямое подтверждение требования контракта: confidence — вспомогательная характеристика,
  не доказательство правильности.
- Координаты слов извлекаются корректно (проверено: `left/top/width/height` для каждого слова).

Полный протокол измерений на тестовом наборе — в `docs/evaluation/ocr_evaluation.md`.

### 3.2 Внешний бенчмарк (контекст, не наш замер)

Публичный бенчмарк 32 OCR-систем на 205 страницах рукописи (Inksight) даёт для латиницы:
Tesseract 5.5.0 — CER 65.6%, EasyOCR 1.7.2 — 58.0%, PaddleOCR-VL-1.6 — 27.4%, лучшие
мультимодальные модели — 8–10%.

**Ограничение этого источника:** в наборе **нет кириллицы и русского языка**, TrOCR не тестировался.
Поэтому цифры нельзя переносить на нашу задачу — они приводятся только как порядок величины,
показывающий разрыв между классическими OCR и VLM на рукописи. Собственные измерения на русском
наборе обязательны, см. `docs/evaluation/ocr_evaluation.md`.

## 5. Решение

**Выбран Tesseract 5 через `pytesseract` (языковая конфигурация `rus+eng`) как основной локальный движок для печатного текста.**

Обоснование:
1. Единственный из локальных вариантов с малой зависимостью, официальной русской моделью и
   выдачей координат и уверенности — то есть полностью закрывает контракт для печатного текста.
2. Лицензия Apache-2.0 совместима с проектом на всех уровнях (движок, модели, обёртка).
3. Воспроизводим: версия движка и файл модели фиксируются, вывод детерминирован.
4. Не требует передачи данных.

**Явно фиксируемое ограничение:** Tesseract **не распознаёт русский рукописный текст**. Ответы,
написанные от руки, будут распознаны плохо или не распознаны вовсе. Это не дефект интеграции, а
свойство движка, и оно должно быть видно пользователю в интерфейсе, а не скрыто.

**Стратегия для рукописи (не реализуется в этом этапе, зафиксирована как следующий шаг):**
- добавить HTR-модель (TrOCR-семейство) как второй адаптер за тем же интерфейсом `OcrEngine`,
  после решения вопроса лицензии `kazars24/trocr-base-handwritten-ru` и выбора детектора строк;
- провести собственную валидацию на целевом домене (тетрадный лист, ручка, освещение), а не
  полагаться на CER из карточки модели;
- облачный OCR держать как отдельную опцию, включаемую только после юридического согласования.

**Чего мы сознательно не делаем:**
- не выбираем облако по умолчанию;
- не включаем VLM-модели в тракт транскрипции (риск галлюцинаций при передаче текста в оценивание);
- не задаём порог «достаточного качества» без измерений на репрезентативном наборе — порог будет
  выведен из данных, а не назначен произвольно.
